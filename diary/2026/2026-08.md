### 振り返り

- 記憶：pull はリモートの main ブランチをローカルの main ブランチに反映するときに使う。
- 記憶：fetch を実行すると、リモートリポジトリの進んだコミットがローカルリポジトリに反映され、リモート追跡ブランチ（remote/origin/main、remote/origin/HEAD）が反映された所まで進む。
- 記憶：ただし、ローカルリポジトリのブランチの HEAD（main・HEAD）の位置は変わらない。
- 記憶：pull は fetch と merge を一緒にしたコマンド。fetch でコミットをローカルリポジトリに反映し、その後 merge（ffmerge）をすることで HEAD を移動することができる。
- 記憶：ローカルからは、リモート追跡ブランチしか見えない。リモート追跡ブランチが fetch や pull で更新されない限り、古いままである。github 上は見えない。
- 記憶：FETCH_HEAD は、fetch を実行したときに fetch 対象のブランチと同じコミットを指すローカルリポジトリにあるポインタ。(「git pull origin main」は「git fetch origin main + git merge FETCH_HEAD」と同等)

- 理解：依存性注入の例:`const sayHello=(name:string, logger:(message:string)=>void){logger(Hello ${name})}`とし、`sayHello("World",console.log)`としている
- 理解：つまり string を受け取り、void を返す関数であれば何でも使えるということである。「(message:string)=>void」という型に依存している。
- 記憶：useState の引数に与えられた数値は初回レンダリング（コンポーネントマウント時）にしか反映されない。再レンダリングされても引数に与えられた数値は反映されない。変数でも関数でも同じ
- 記憶：useState の引数に関数の実行結果を渡したいときは関数名だけ登録する。そうすると初回レンダリングのみ関数が実行され、以降は実行されない。関数呼び出し「()」をした場合は、レンダリング毎に関数が実行される
- 記憶：Props で渡した変数をレンダリングごとに state に反映させたいときは、useEffect などで setState を実行する
- 記憶：useRef も同様である`const originalThemeRef = useRef(currentTheme)`では初回レンダリングで`originalThemeRef.current = currentTheme`となるが 2 回目以降に渡した currentTheme は無視される
- 記憶：リモートブランチの削除：1.Github 上で削除 2.ローカルリポジトリで `git push origin --delete <ブランチ名>` または `git push origin :<ブランチ名>`
- 記憶：リモートブランチの削除コマンドを実行したユーザのローカルリポジトリのリモート追跡ブランチは削除されるが、別のユーザがリモートブランチを削除した場合は自分のローカルリポジトリのリモート追跡ブランチは削除されない
- 記憶：`git fetch --prune`または`git remote prune origin`を実行する。リモートリポジトリには存在しないが、ローカルに残っているすべてのリモート追跡ブランチを削除する
